# 代码风格

[English](../../docs/develop/code_style.md) | [模块](modules_cn.md)

本页是 Dual Nero VLA 第一方代码的风格。它不改写 `AgileX/`。厂商文件保持上游布局，以便继续和官方 Nero SDK 对照。

## 仓库配置

`.clang-format` 是 C++ 格式化配置，使用 Google 风格，行宽 100。`.editorconfig` 规定普通文本使用 UTF-8、LF 和两空格缩进。Python 文件使用四空格，因为 Python 格式化工具按这个宽度工作。不要另加只属于某个编辑器的设置目录。

根目录 `CMakeLists.txt` 固定 C++20，要求该标准，并关闭编译器扩展。以后每个编译模块都有自己的 `CMakeLists.txt`，列出源文件，并声明公开与私有头文件路径和链接依赖。公开头文件放在该模块的 `include/`。私有辅助代码留在模块内或 `detail/`，不被外部包含。根文件按依赖顺序加入模块。生成的接口目标通过辅助函数引用，不手写生成路径。

## 注释与头文件

注释和文档字符串使用英文。它们记录不明显的约束、单位、所有权、并发规则或失败方式，不重复一个已经清楚的名字。公开的 C++ 声明在调用方需要这些信息才能安全使用时，说明所有权、调用是否阻塞，以及如何报告错误。这些声明上的简短 Doxygen 就够了。生成的 Doxygen 输出不手工修改。

## Python

第一个 Python 包以 Python 3.12 为目标。公开函数带类型标注。签名没有表达清楚的契约，用简短文档字符串说明。不明显的数值限制、硬件假设和失败行为用英文注释说明。加入该包时，把类型检查配置写进它的 `pyproject.toml`。

## 测试与日志

测试命名为 `test_<对象>_<条件>_<期望>`。单元测试喂入模拟对象或桩，不依赖真机。在模块文档里写明方法：带模拟的单元测试、桩集成、vcan、回放，或人工真机验收。本产品以后发出的日志遵循[日志](../debug/logging_cn.md)里的记录格式。日志不包含密钥、原始图像、提示词或无界载荷。

提交前用这里声明的工具做格式化、静态检查和测试。只改格式的提交与行为修改分开，以免混在一起的差异看不出行为变化。
